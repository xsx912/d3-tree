# 测试规范

本仓库对测试用例的编写与修改约束。code-review 的 Standards 轴以此为准；`/implement` 写测试时必须遵守。

## 三条硬纪律（防"测试同义反复"）

### 1. 期望值必须独立推导

断言的期望值只能来自 **fixture 数据的算术**、**几何/物理不变式**、或 **规格文本**——禁止从实现的运行结果抄回（"跑一遍 → 把实际值填进断言"）。

- 正确：`root + a + 5 个可见子 + 聚合 = 15` 是数出来的；`根节点屏幕坐标 tx + k×视口宽/2 = 视口中心` 是几何推导
- 错误：`expect(nodes.length).toBe(实际观测值)`

### 2. bug 修复必须携带能杀死该 bug 的回归测试

修 bug 的提交里必须包含一条新测试，且作者要能回答：**"把修复代码还原回去，这条测试会红吗？"** 答不上来的回归测试不算数。允许从弱变强（如 zoomToFit 从只断言 scale 加强为断言居中不变式），不允许反向削弱。

### 3. 代码与测试冲突 = 规格缺口，禁止静默对齐

实现和测试不一致且双方都合理时（如 collapseAll 收起到哪一级），不是谁对谁错，是规格没写清。裁决结果必须三处同步落盘：**测试断言 + API 文档注释 + 工单/spec 描述**。只改测试去迁就实现，视为违规。

## 辅助约定

- **修改既有测试期望**时，提交信息必须注明理由，且只能是三类之一：算术/推导修正、规格决策记录、测试加强
- 工具已强制的（类型、格式化）不重复测试
- 本仓库测试先例与单缝原则见 `.scratch/bidirectional-tree/spec.md` 的 Testing Decisions（公共 API 外部行为断言、jsdom、注入度量保证确定性）；新特性 spec 沿用该范式
